(Link from Product Page → Full Article in Blog)

Product page (Vendure-powered): Clean, commerce-focused, short teaser + link
→ "Full story" button/link
Blog / Article page (Payload-powered): Full long-form story, images, rich formatting
→ Lives under /blog/[slug] or /articles/[slug]

This keeps the product page fast/lightweight and gives the full storytelling experience in a dedicated blog-style page.
Recommended Implementation (Vue 3 Storefront)
1. Product Detail Page – Add Link Only
In your product page component (e.g. ProductDetail.vue):
vue<template>
  <div class="product-page">
    <!-- Your existing Vendure commerce content -->
    <h1>{{ product.name }}</h1>
    <p class="price">฿{{ formatPrice(product.variants[0].price) }}</p>
    <!-- ... variants, add to cart, images ... -->

    <!-- Teaser + Link to full story -->
    <div class="story-teaser mt-8 border-t pt-6">
      <h3 class="text-xl font-semibold mb-3">Discover the Full Story</h3>
      <p class="text-gray-600 mb-4">
        Learn why this laptop is perfect for students, its battery life secrets, and more...
      </p>

      <router-link
        :to="`/blog/${product.slug}`"
        class="inline-flex items-center px-6 py-3 bg-blue-600 text-white rounded-lg hover:bg-blue-700 transition"
      >
        Read the Full Article
        <ArrowRightIcon class="ml-2 w-5 h-5" />
      </router-link>
    </div>
  </div>
</template>
→ This keeps the product page clean and focused on buying.
2. Create Blog/Article Page – Fetch from Payload by Product Slug or ID
Create a new page/route: /blog/[slug].vue
vue<!-- pages/blog/[slug].vue -->
<template>
  <div class="blog-article container mx-auto px-4 py-12 max-w-4xl">
    <!-- Loading state -->
    <div v-if="loading" class="text-center py-20">Loading story...</div>

    <!-- Not found -->
    <div v-else-if="!article" class="text-center py-20">
      <h2 class="text-2xl">Story not found</h2>
      <p class="mt-4">This product story is still being prepared.</p>
    </div>

    <!-- Full article -->
    <article v-else>
      <h1 class="text-4xl font-bold mb-6">{{ article.name }}</h1>

      <!-- Hero image -->
      <img
        v-if="article.heroImage?.url"
        :src="article.heroImage.url"
        :alt="article.name"
        class="w-full h-auto rounded-xl shadow-lg mb-10 object-cover"
      />

      <!-- Rich content -->
      <div
        v-if="article.richDescription?.html"
        class="prose prose-lg prose-blue max-w-none"
        v-html="article.richDescription.html"
      ></div>

      <!-- Gallery of additional images -->
      <div v-if="article.storyImages?.length" class="mt-12 grid grid-cols-1 md:grid-cols-2 gap-6">
        <div v-for="item in article.storyImages" :key="item.image.id">
          <img
            :src="item.image.url"
            :alt="item.caption || article.name"
            class="w-full h-auto rounded-lg shadow"
          />
          <p v-if="item.caption" class="text-center text-sm text-gray-600 mt-2">
            {{ item.caption }}
          </p>
        </div>
      </div>

      <!-- Back button -->
      <div class="mt-12 text-center">
        <router-link to="/products" class="text-blue-600 hover:underline">
          ← Back to Products
        </router-link>
      </div>
    </article>
  </div>
</template>

<script setup>
const route = useRoute()
const slug = route.params.slug
const loading = ref(true)
const article = ref(null)

try {
  // Fetch by slug (most reliable & SEO-friendly)
  const response = await $fetch(`/api/vendure-product`, {
    query: {
      where: { slug: { equals: slug } },
      limit: 1,
      depth: 2,           // Get full relations (heroImage, storyImages)
      draft: false
    }
  })

  article.value = response.docs?.[0] || null
} catch (err) {
  console.error('Failed to load story:', err)
} finally {
  loading.value = false
}
</script>

<style>
.prose img {
  @apply rounded-lg shadow-md my-6;
}
</style>
Key Points in the Code Above

Uses slug in URL (/blog/laptop) — beautiful, SEO-friendly, shareable
Fetches the exact product by slug (same as Vendure product slug)
depth=2 → gets full media objects (urls, sizes) for images
Mobile-friendly: prose class (from Tailwind Typography) makes rich text look great on small screens
Fallbacks: loading state + not-found message



Bonus: Alternative Fetch by ID (if you prefer)
If you ever want to use ID instead of slug:
TypeScriptconst productIdFromVendure = 1  // from Vendure data
const response = await $fetch(`/api/vendure-product/${productIdFromVendure}`, {
  query: { depth: 2, draft: false }
})
But slug is better for URLs.
Final Result

Product page: short, fast, only commerce + nice "Read the Full Article" button
/blog/laptop: full beautiful story, hero image, gallery, rich text — perfect for mobile reading

This is very professional — many modern e-commerce sites (especially in fashion/tech) use this exact pattern.
