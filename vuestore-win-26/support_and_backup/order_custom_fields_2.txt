Gemini replied
1. Should you add nullable: true?
Short Answer: No.

For a list: true relation (which creates a list of items), you generally do not need nullable: true.

In Database: It uses a separate "join table", so there is no column in the Order table that needs to be nullable.

In Logic: If there are no images, the value is simply an empty array []. This is cleaner than dealing with null.

In TypeScript: If you make it nullable, you have to constantly check if (order.customFields.paymentProofs) before iterating. Keeping it non-nullable guarantees you always get an array (even if empty), which is easier to work with.

2. Vue 3 Implementation
Crucial Warning: By default, the Vendure Shop API does not allow users to upload files (the createAssets mutation is protected for Admins only).

To make this work, you likely have a custom plugin or mutation (e.g., uploadCustomerAsset). The example below assumes you have a GraphQL mutation enabled for the Shop API that accepts a file and returns an Asset.

Here is a complete Vue 3 Composition API example:

HTML
<template>
  <div class="upload-section">
    <h3>Upload Payment Proofs</h3>
    
    <!-- File Input -->
    <input 
      type="file" 
      multiple 
      accept="image/*" 
      @change="handleFiles" 
      :disabled="isUploading"
    />

    <!-- Preview List -->
    <div class="preview-list" v-if="uploadedAssets.length">
      <div v-for="asset in uploadedAssets" :key="asset.id" class="preview-item">
        <img :src="asset.preview" />
        <span>Uploaded</span>
      </div>
    </div>

    <!-- Status -->
    <p v-if="isUploading">Uploading...</p>
    <p v-if="errorMessage" class="error">{{ errorMessage }}</p>
  </div>
</template>

<script setup lang="ts">
import { ref } from 'vue';

// State
const isUploading = ref(false);
const errorMessage = ref('');
const uploadedAssets = ref<Array<{ id: string; preview: string }>>([]);

// 1. Handle File Selection
const handleFiles = async (event: Event) => {
  const input = event.target as HTMLInputElement;
  if (!input.files?.length) return;

  isUploading.value = true;
  errorMessage.value = '';

  try {
    const newAssetIds: string[] = [];

    // Upload each file one by one (or in parallel)
    for (const file of Array.from(input.files)) {
      const asset = await uploadFileToVendure(file);
      if (asset && asset.id) {
        uploadedAssets.value.push(asset);
        newAssetIds.push(asset.id);
      }
    }

    // After uploading files, link them to the Order
    if (newAssetIds.length > 0) {
      await linkAssetsToOrder(newAssetIds);
    }

  } catch (err) {
    console.error(err);
    errorMessage.value = 'Upload failed. Please try again.';
  } finally {
    isUploading.value = false;
    // Clear input so user can select same file again if needed
    input.value = ''; 
  }
};

// 2. Upload Function (GraphQL Multipart Request)
// NOTE: This assumes you have an 'uploadFile' mutation exposed to Shop API
async function uploadFileToVendure(file: File) {
  const formData = new FormData();
  
  // Standard GraphQL Multipart Request Specification
  const operations = {
    query: `mutation ($file: Upload!) { 
      uploadFile(file: $file) { 
        id 
        preview 
      } 
    }`,
    variables: { file: null }
  };
  
  formData.append('operations', JSON.stringify(operations));
  formData.append('map', JSON.stringify({ '0': ['variables.file'] }));
  formData.append('0', file);

  const response = await fetch('http://localhost:3000/shop-api', {
    method: 'POST',
    headers: {
      // Don't set Content-Type here; let browser set it with boundary for FormData
      'Authorization': 'Bearer ' + localStorage.getItem('auth-token'), // If you use tokens
    },
    body: formData,
  });

  const json = await response.json();
  if (json.errors) throw new Error(json.errors[0].message);
  
  return json.data.uploadFile;
}

// 3. Link to Order Function
async function linkAssetsToOrder(assetIds: string[]) {
  // We need to append new IDs to existing ones if we want to keep old uploads,
  // but for simplicity, this example sends the list of NEWly uploaded IDs.
  // In a real app, you should merge with existing IDs from the order.

  const query = `
    mutation LinkProofs($ids: [ID!]) {
      setOrderCustomFields(input: {
        customFields: {
          paymentProofs: $ids
        }
      }) {
        ... on Order {
          id
          code
        }
      }
    }
  `;

  const response = await fetch('http://localhost:3000/shop-api', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      // Include auth token/cookie
    },
    body: JSON.stringify({
      query,
      variables: { ids: assetIds } // Note: if you want to ADD, you must pass [oldIds, ...newIds]
    })
  });

  const json = await response.json();
  if (json.errors) throw new Error(json.errors[0].message);
  
  console.log('Order updated with proofs');
}
</script>

}

Key Logic Explained:
Multipart Request: File uploads in GraphQL require a specific "Multipart" format (using operations, map, and the file blob). The uploadFileToVendure function handles this manually since standard fetch doesn't know GraphQL structure.

uploadFile Mutation: I used a placeholder name uploadFile. You must check what your backend actually calls this mutation. If you haven't installed a plugin for customer uploads, this part will fail.

Linking (setOrderCustomFields):

Important: The setOrderCustomFields mutation overwrites the list.

If a user uploads 1 image, then uploads another 1 image later, you must send both IDs in the second request ([ID1, ID2]).

In my simple example, I just send the new IDs. In production, you should read order.customFields.paymentProofs first, add the new ID to that array, and send the combined list.
